## 1. DES (Data Encryption Standard)

**DES (Data Encryption Standard)** — симметричный блочный шифр, построенный по схеме сети Фейстеля

Блочный шифр — это функция, которая шифрует данные фиксированными блоками одинакового размера.

Поточный шифр — данные обрабатываются побитно/побайтно непрерывным потоком.

Ключевое свойство сети Фейстеля, что функция $F$ не обязана быть обратимой

---

## 2. Полная схема

Пусть функции:
- $G$ — вычисление $F$ и XOR
- $T$ (transposition) — перестановка местами $L$ и $R$

```text
Encryption:  G1 → T → G2 → T → . . . G2n → (T)
             └──────┘  └──────┘        └──────┘
             round 1   round 2        last round
```

Иногда в самом конце добавляют финальную перестановку $T$, иногда — нет.

**Расшифрование**

```text
Decryption:  G2n → T → G2n-1 → T → . . . → G1  T
```

Иногда эту сеть называют **сетью Фейстеля-Люцифера**, по названию раннего шифра Lucifer, из которого исторически развился DES.

---

## 3. Начальная и финальная перестановки (IP)

<u>IP</u> (initial permutation) — начальная перестановка

$IP^{-1}$ — обратная перестановка, восстанавливающая исходный порядок битов.

```text
┌──────────────┐          ┌──────────────┐            ┌────────────┐
│Открытый текст│ → (IP) → │  16 раундов  │ → (IP⁻¹) → │ Шифротекст │
│    m ∈ M     │          │сети Фейстеля │            │   c ∈ C    │
└──────────────┘          └──────────────┘            └────────────┘
```

Это безключевое преобразование (не зависит от ключа) — оно не добавляет криптографической стойкости, а исторически было связано с удобством аппаратной реализации на оборудовании 1970-х годов

**Шаблонные** методы — это режимы работы блочного шифра. Они определяют, как блочный шифр применяется к сообщению произвольной длины

```text
IP → E → IP⁻¹ → IP → D → IP⁻¹
↑    ↑     ↑         ↑
│ шифрование│      расшифрование
└───────────┘
это разные перестановки!
Они заданы различными таблицами
```

## 4. Генерация раундовых ключей

Вход: 64 бита (из них 56 значащих)

### 1. Биты контроля чётности

Из 64 битного ключа сначала удаляются 8 бит чётности — по одному на каждый байт.

> Сумма единиц в байте (включая бит чётности) должна быть нечётной

```text
┌─┬───────┬─┬───────┬─┬───────┬─┬───────┬─┬───────┬─┬───────┬─┬───────┬─┬───────┐
│X│       │X│       │X│       │X│       │X│       │X│       │X│       │X│       │
└─┴───────┴─┴───────┴─┴───────┴─┴───────┴─┴───────┴─┴───────┴─┴───────┴─┴───────┘
 ↑
биты контроля чётности
```

### 2. PC-1 и разбиение на $C_0, D_0$

Оставшиеся 56 бит проходят через перестановку PC-1 (permutation choice 1) и делятся на два блока по 28 бит: $C_1$ и $D_1$

### 3. Циклические сдвиги

На каждом из 16 раундов оба блока сдвигаются циклически влево

$$i: 1\text{–}16 \qquad C_{i+1} = C_i \lll 1 \text{ или } 2$$

$$D_{i+1} = D_i \lll 1 \text{ или } 2$$

где
- 1 сдвиг (бит) — для раундов 1, 2, 9, 16
- 2 бита — для раундов всех остальных

> **Как запомнить?**
>
> ```text
>  1    2    9    16
>  ‖    ‖    ‖    ‖
>  1¹   2¹   3²   4²
> ```

Изначально:

```text
┌──────────┬──────────┐
│          │          │
└──────────┴──────────┘
     C1         D1
```

### 4. Получение <u>раундового</u> ключа.

Конкатенация $C_i D_i$ проходит через перестановку PC-2, которая сжимает 56 бит до 48 бит — это и есть раундовый ключ $RK_i$, используемый в раунде $i$

---

## 5. Раундовая функция

Функция $F$ принимает
- $BH_i$ (block half) — половину блока данных (32 бита)
- раундовый ключ $RK_i$ (48 бит)

**Шаги:**

### 1. Таблица расширения E

Таблица расширения $E$ превращает 32-битный блок $BH_i$ в 48 битный, дублируя часть битов (**расширяющий алгоритм**). Обычно 32 бита разбиваются на 8 групп по 4 бита, и к каждой группе добавляется по одному биту от соседних групп

```text
│1-4│  │5-8│  │9-12│  │13-16│  │17-20│  │21-24│  │25-28│  │29-32│
   ╲      │      ╱
  бит 4   │    бит 9
последний │   первый бит
   бит    │
      ↘   ↓   ↙
│E1│  │ E2 │  │E3│  │E4│  │E5│  │E6│  │E7│  │E8│

32 → │ 1  2  3  4 │ ← 5

 4 → │ 5  6  7  8 │ ← 9

 8 → │ 9 10 11 12 │ ← 13
```

### 2. XOR с раундовым ключом

$$E(BH_i) \oplus RK_i \;\to\; 48 \text{ бит}$$

### 3. Сжатие.

Результат (48 бит) разбивается на 8 блоков по 6 бит, каждый обрабатывается своим S-блоком.

**S-блок** — это таблица подстановки, сжимающая 6 бит в 4 бита

```text
  b1 │ b2 b3 b4 b5 │ b6
  └──┼─────────────┼──┘ ──▶ b1b6      — определяет номер строки
     └─────────────┘    ──▶ b2b3b4b5  — номер столбца
```

| | 0000 | 0001 | … | 1111 |
|---|---|---|---|---|
| **00** | | | | |
| **01** | | | | |
| **10** | | | | |
| **11** | | | | |

— таблица для S-преобразования

### 4. Перестановка P

Результат работы восьми S-блоков (32 бита) проходит через фиксированную перестановку $P$, которая перемешивает биты между собой → это финальный результат $F$

---

## 6. Слабые ключи

**Слабые ключи** — ключи, при которых все 16 раундовых ключей получаются одинаковыми.

В этом случае шифрование, применённое дважды с таким ключом, вернёт исходный текст — шифр становится инволюцией.

---

## 7. Конфузия и диффузия

**Конфузия (confusion)** — свойство шифра максимально усложнять зависимость между ключом и шифротекстом, делая статистическую связь между ними как можно менее очевидной.

**Диффузия (diffusion)** — свойство шифра «размазывать» влияние одного бита открытого текста (или ключа) на как можно большее число бит шифротекста, так что изменение одного входного бита меняет в среднем половину выходных битов (**лавинный эффект**)
