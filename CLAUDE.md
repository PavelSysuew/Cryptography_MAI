## О проекте

Лабораторные работы по криптографии (МАИ, 3 курс, 1 семестр). C++17, сборка через CMake.
Текст задания лежит в `Задание.pdf` (корень репозитория) — «Задания к работе №1 по основам криптографии».

### Ограничения задания

- Язык объектно-ориентированный (C++).
- **Готовые реализации алгоритмов защиты информации и криптобиблиотеки использовать нельзя** — всё пишется вручную (DES, DEAL, режимы, набивка).

### Пункты работы №1

1. Функция перестановки бит над массивом байтов: значение, P-блок, порядок индексации (от младшего к старшему или наоборот), номер начального бита 0 или 1. **Готово** (`lab1/task1`).
2. Интерфейсы: (2.1) расширение ключа (ключ → массив раундовых ключей), (2.2) шифрующее преобразование (блок + раундовый ключ → блок), (3) [де]шифрование симметричным алгоритмом с заранее заданными раундовыми ключами. Затем класс-контекст симметричного алгоритма:
   - режимы шифрования (enum): ECB, CBC, PCBC, CFB, OFB, CTR, Random Delta;
   - режимы набивки (enum): Zeros, ANSI X.923, PKCS7, ISO 10126;
   - конструктор: ключ, режим шифрования, режим набивки, IV (опционально), доп. параметры (переменное число аргументов);
   - методы [де]шифрования: данные (массив байтов произвольной длины) + ссылка на результат, либо путь входного файла + путь выходного;
   - где возможно — распараллеливание; операции должны выполняться **асинхронно**.
3. Класс сети Фейстеля на базе интерфейса 2.2; конструктор принимает реализации 2.1 и 2.2.
4. DES на базе класса из п. 3 (свои реализации 2.1 и 2.2); использовать функцию перестановки бит из п. 1.
5. Демонстрация DES: шифрование/дешифрование случайных байтов и файлов (текст, музыка, изображения, видео, исходники и т. д.) во всех режимах, на типах из п. 2–4.
6. DEAL на базе класса из п. 3 (свои 2.1 и 2.2); адаптер, позволяющий использовать DES как раундовую функцию F.
7. Демонстрация DEAL на файлах/данных в разных режимах, на типах из п. 2–6.

Как пункты задания раскладываются по `labN/taskM` — пока не определено: `lab1/task1` = п. 1, `lab1/task2` — заглушка.

## Структура

```
CMakeLists.txt          корневая сборка, по одной цели на задачу
build/                  каталог сборки (в git только .gitkeep)
lab1/task1/             перестановка бит (п. 1)
  main.cpp              демонстрация: печать результата в bin и hex
  include/bitsPermutation.h
  src/bitsPermutation.cpp
lab1/task2/main.cpp     заглушка ("Lab 1, task 2")
```

Раскладка задачи: `main.cpp` в корне задачи, заголовки в `include/`, реализация в `src/`.
Новая задача — по образцу `lab1_task1` в `CMakeLists.txt` (закомментированный шаблон для `lab1_task2` уже есть): `add_executable`, `target_include_directories(... PRIVATE labN/taskM/include)`, флаги `-Wall -Wextra` (`/W4` для MSVC).
Для асинхронности/потоков (`std::async`, `std::thread`) в CMake понадобится `find_package(Threads)` и линковка с `Threads::Threads`.


Проверено: собирается без предупреждений (g++ 13.3, cmake). Тестов и линтера нет.

## Стиль кода

- 4 пробела, `#pragma once`, `using namespace std;` в `.cpp` (в заголовках — с `std::`).
- Идентификаторы: функции и `enum class` в camelCase (`bitsPermutation`, `bitOrder::rightToLeft`), файлы называются по основной сущности (`bitsPermutation.h/.cpp`).
- Комментарии и Doxygen-описания (`@param`, `@return`, `@throws`) — на русском; вспомогательные функции в анонимном `namespace` в `.cpp`.
- Байтовые данные — `std::vector<uint8_t>`, размеры и номера бит — `size_t`.
- Ошибки аргументов — `std::invalid_argument`; в `main.cpp` перехватываются и печатаются как «Ошибка: ...».

## lab1/task1: bitsPermutation

`std::vector<uint8_t> bitsPermutation(input, pBlock, order = rightToLeft, firstElement = 0)`

- `pBlock[i]` — номер бита входа, который встанет на позицию `i` результата; размер `pBlock` = число бит результата (может быть короче/длиннее входа, номера могут повторяться).
- `firstElement` (0 или 1) относится к номерам в `pBlock`. Результат — `ceil(pBlock.size() / 8)` байт, неиспользуемые биты последнего байта нулевые.
- Бросает `invalid_argument`: `firstElement` не 0/1, пустой `pBlock`, номер вне диапазона. (Про пустой `pBlock` в doc-комментарии заголовка не сказано.)
- Для одного байта работает верно (проверено на `0b10110001`, `{1,2,3,1,2,3,0,7}`: rightToLeft → `C0`, leftToRight → `6F`).

**Не проверено / возможное несоответствие:** заголовок говорит, что байты массива всегда идут слева направо и результат пишется в той же нумерации, что и вход. Но при `rightToLeft` в конце `bitsPermutation.cpp` результат разворачивается (`std::reverse` по байтам), а вход — нет. Для входа из нескольких байтов порядок байт результата стоит проверить отдельно, прежде чем использовать функцию в DES (P-блоки, IP/FP и т. п. работают на многобайтных данных).
